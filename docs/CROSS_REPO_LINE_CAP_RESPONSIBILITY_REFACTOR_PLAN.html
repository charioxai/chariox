Cross-Repo Line Cap and Responsibility Refactor

Plan to refactor arroba and the sibling arroba-cloud repository so hand-authored files stay below 1000 lines and responsibility boundaries are explicit, while current runtime behavior keeps working during migration.

Primary rule

The kernel remains the runtime authority. Refactors must preserve the existing kernel, relay, provider, Cloud, local TUI, remote TUI, web terminal, and native TUI authority boundaries while moving code into smaller modules.

Line-Cap Policy

Enforce

  • Hand-authored source files, tests, scripts, docs, schemas, and styles must be no more than 1000 lines.
  • Add a line-cap checker in both repos that scans git ls-files.
  • Start in report mode with a checked-in allowlist of current offenders.
  • Fail CI on new offenders immediately; shrink the allowlist as files are split.
  • Switch to hard fail with an empty allowlist after the migration is complete.

Exclude

  • Package lockfiles and generated lock artifacts.
  • Generated fragments such as existing *.mjsfrag and *.tsfrag files.
  • Binary assets, screenshots, and snapshots that are intentionally mechanical.
  • Build outputs and cache files not intended as source.

Migration Safety

  1. Preserve public APIs and import paths first. Old large files become small facades until all callers are migrated.
  2. Separate pure moves from behavior edits. A refactor PR should either move code or change one extracted behavior with focused tests.
  3. Do not change serialized protocol shapes as part of this work. If unavoidable, bump the shared local daemon protocol version, update snapshot/hash tests, update client minimums only when needed, and add a focused drill.
  4. Keep relay transport-only. Do not move session authority, prompt inspection, provider payload handling, workspace data, or history into relay or Cloud.
  5. Extract drill harnesses before splitting scenario scripts, so existing package scripts remain stable.
  6. Preserve current dirty worktree changes by treating them as user-owned during implementation.
