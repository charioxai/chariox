# MP-08/MP-10/MP-11 native Linux display pipeline

Build the Linux kernel with `--features native-display` and development libraries for X11, Xext, Xdamage, Xcomposite, Xtst, static libyuv and static libwebp/libsharpyuv (protocol 466 lossless tiles), plus x264 and libavcodec/libavutil headers. Codec libraries are never linked into the kernel (owner decision 2026-10-09, as Selkies): the worker loads them at runtime. OpenH264 (Cisco's binary, ABI `libopenh264.so.8`, or an absolute `CHARIOX_BROWSER_DISPLAY_OPENH264`) is the default encoder, matching the vendored OpenH264 2.6 API headers (BSD-2-Clause); x264 (`libx264.so.<X264_BUILD>`) is optional, selected by `CHARIOX_BROWSER_DISPLAY_SOFTWARE_ENCODER=libx264` or used when OpenH264 is absent; libavcodec (`libavcodec.so.<major>`) decodes for the output guard and drives VAAPI. Without libavcodec or any encoder the native codec reports unavailable. The optional feature preserves builds without those libraries and non-Linux paths. `CHARIOX_NATIVE_DISPLAY_INCLUDE` and `CHARIOX_NATIVE_DISPLAY_LIB` are build-only search paths. The Linux production kernel launches its own ELF with the internal worker entry; test harnesses supply the production worker ELF explicitly.

MP-08/MP-10: one native child owns XShm window readback, exact damage comparisons, immutable mapped leases, masking, libyuv conversion, H264 encode/decode guard, packet files and PNG repair. Node owns admitted control, CDP document/visibility/protection fences and client sequencing. The native worker sees geometry and masks, never protected values or provider state. Existing unshared/CDP and non-H264 fallback stays compatible.

MP-11: the helper requires one Chromium-owned window, exact pixel format/geometry, private owned kernel-created directories, fixed slot leases and bounded commands. Masks intersect viewport bounds before pointer arithmetic. Protected codec output is decoded and checked independently; failure discards every lossy row and presents masked lossless pixels. x264 masks use per-macroblock quant offsets; OpenH264 has none, so its protected rows cap QP at 36. Unprotected x264 output uses full x264 reconstruction for neutral-pixel exact certificates; OpenH264 and VAAPI rows certify from an independent decode. Packet hydration pins names, owner, regular-file type, size, headers, geometry and one-shot consumption. Kernel cleanup still reclaims captured slots and Xauthority after supervisor death; shared-memory segments are immediately marked IPC_RMID.

MP-08/MP-10: exact preparation may omit only literal neutral black/white certified against the delivered codec revision, or RGB equal to a delivered lossless overlay. Colored decoder reconstruction is never inferred from GPU rounding. Undelivered revisions, changed masks or missing references require opaque repair. Global revisions prevent encoder-reset ABA; input/document/policy/lease fences also gate handoff and commit.

MP-08/MP-10: `CHARIOX_BROWSER_DISPLAY_SOFTWARE=1` requests the software encoder (OpenH264 by default). Otherwise the native codec attempts an accessible render node with libavcodec h264_vaapi using the same mask/conversion/output guards. Missing/failed hardware falls back with an explicit diagnostic. Successful packet traces, not device presence or requested flags, establish hardware use.

MP-08/MP-10: mutations remain serial independently of capture. Per-credit supervisor liveness uses owned child exit detection; startup and explicit health retain health RPCs. A successful protection policy cache belongs only to that child; any change crosses the original barrier and respawn drops the cache. Public serialized frame and daemon/relay contracts remain unchanged.

MP-10: component fixtures and native contracts are supplementary. Performance thresholds, unchanged masking/crash gates, actual real-app/hosted public-site DPR1/2 drills and multi-hour stability must all pass before acceptance. Retain source-bound measurements and acceptance receipts outside the repository.
