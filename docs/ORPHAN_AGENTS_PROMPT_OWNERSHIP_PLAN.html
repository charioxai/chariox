Orphan Agents And Prompt Ownership

Implementation plan for managing externally created provider threads as Arroba agents, with prompt-level ownership and consistent web/TUI behavior.

Summary

Implement the product model as agent threads plus prompt ownership, not session ownership. Provider threads created outside Arroba are shown as orphan agents until attached to exactly one Arroba session.

Once attached, Arroba observes external prompts and output, labels those turns as external, and queues Arroba-origin prompts behind any active provider turn instead of steering into it.

Keep the existing kernel wire names ExternalProviderSession* for this pass to avoid broad protocol churn, but rename product and UI language to orphan agents in web and TUI. Add protocol fields only where needed for prompt ownership and steering policy.

Kernel And Protocol

  • Treat ListExternalProviderSessions as the orphan-agent list.
  • Return only unattached provider threads by default.
  • Reject ImportExternalProviderSession and ImportExternalProviderAgent if the external provider thread is already attached to another Arroba agent.
  • Keep WatchExternalProviderSessionStatus able to report imported by id for stale UI and status checks.
  • Add prompt_origin: "arroba" | "external" to PromptQueueItem, defaulting to arroba.
  • Bump the local daemon protocol version and update protocol shape/hash tests.
  • External observed active turns create a non-dispatchable active prompt marker with prompt_origin="external" and status running.
  • Key provider-thread activity by provider plus provider session id for imported/orphan-attached agents.
  • Queue Arroba prompts submitted while that provider thread is externally active.
  • Reject and disable SteerQueuedPrompt when the target agent's active prompt origin is external.
  • After the external turn settles, resume normal queued prompt dispatch.
  • Keep existing observed-history import behavior, but support mutable/upserted observed entries by merge key so partial provider updates can refresh instead of being skipped.
  • Preserve SessionHistoryEntrySource::ExternalProviderObserved for external prompt/output labeling.
  • Surface whatever each provider persists: Codex JSONL, OpenCode SQLite/WAL, and Claude history/hooks. Do not invent unavailable hidden traces.

Web And TUI

  • Rename web waiting-room "External sessions" rows and labels to Orphan agents.
  • Selecting an orphan agent under "Existing sessions" imports it as a new Arroba session with that agent as the first agent.
  • After import, remove the orphan agent from the orphan list.
  • Use two tabs in the web freeform spawn dialog: New agent and Orphan agents.
  • Selecting an orphan agent in the freeform dialog attaches it to the current session instead of launching a new provider thread.
  • Label external observed prompts and outputs as external in the web terminal transcript.
  • If queued Arroba prompts are blocked behind an external active turn, show them queued but disable steer; keep cancel enabled for Arroba-owned queued prompts.
  • Rename TUI waiting-room external-provider copy to Orphan agents.
  • Keep the existing TUI activation path importing an orphan as a new session, now framed as "opened orphan agent".
  • Keep /agent spawn --external-session-id as a compatibility alias.
  • Add /agent spawn --orphan-agent <id> and update command-center/help wording to use orphan-agent language.
  • Render external observed entries with an external marker in TUI transcripts.
  • Disable or hide queued prompt steer when the target active prompt is external.

Live Drills

  • Web discovery/import drill: start the OSS kernel on the web-dev port and open the web terminal; create a Codex thread outside Arroba; verify it appears under Orphan agents; open it from waiting room; verify a new Arroba session is created with that agent and the orphan row disappears.
  • Web attach drill: create another external provider thread; open an existing Arroba session; use freeform spawn dialog to attach it from Orphan agents; verify it appears as an agent in that session and disappears from orphan listings.
  • External live observation drill: for Codex, OpenCode, and Claude, prompt the attached provider thread from the external terminal/app; verify Arroba shows the external prompt and best-available persisted output/status with external labels.
  • External metadata drill: for Codex, OpenCode, and Claude, capture an external turn that includes provider-visible metadata such as turn id, status/running state, reasoning or thinking summary when persisted, tool calls/results when persisted, timestamps, model/provider identity, and completion/error state; verify Arroba displays every available metadata field live or near-live without implying unavailable token traces exist.
  • External queueing drill: submit an Arroba prompt while the external turn is active; verify it queues, steer is disabled, and it dispatches only after the external turn settles.
  • Coexistence drill: while an Arroba-owned prompt is active, submit a prompt from the external terminal; verify Arroba labels the external turn, keeps its own queue consistent, and does not crash or fork the Arroba session.
  • TUI parity drill: repeat discovery/import and attach flows in the TUI waiting room and /agent spawn --orphan-agent; verify external labels and disabled steering match web behavior.

Assumptions

  • First implementation keeps ExternalProviderSession* as internal and wire naming, changing product language in projections and UI. Full protocol renaming can be a later cleanup.
  • Live external output means "as live as provider persistence allows"; token-level streams are only available when Arroba owns or hooks the provider process.
  • Arroba will not try to block external terminals from submitting prompts. It will observe, label, reconcile, and serialize Arroba-origin prompts around detected external activity.
