Agent Pane Footer Dropdown Plan

Updated plan for simplifying crowded agent pane footers in both the local TUI and the web terminal.

Target footer shape
STATUS | alias | view slice? | dropdown

All clickable controls except the optional slice screen link should live under the dropdown at every pane width.

Scope

  1. Cover the OSS/local TUI in chariox: apps/cli/src/split-pane-footer.ts and apps/cli/src/split-pane-footer-renderer.ts.
  2. Cover the web terminal in chariox-cloud: apps/web/src/react/terminal/FreeformPaneShellMount.tsx, apps/web/src/react/terminal/FreeformFooterControlsMount.tsx, apps/web/src/terminal/freeform-footer-controls-controller.ts, apps/web/src/terminal/freeform-agent-projection.ts, and apps/web/src/styles/freeform.ts.

Footer Behavior

  1. Keep only the status badge, visible alias, optional view slice link, and dropdown trigger inline.
  2. Remove the visible agent ID or agentRef from the footer row. The alias remains the identity shown there.
  3. Remove inline runtime facts: home machine..., local wt..., local run, provider run, worktree, worker run, auth, manifest, and extension badges.
  4. Preserve runtime facts in inspect/detail surfaces, not in the pane footer.
  5. Show view slice before the dropdown only when the agent is in a slice with a display URL.

Dropdown Rules

  1. Always render the dropdown, regardless of pane width.
  2. Move provider, model, variant, mode, and permission controls into the dropdown.
  3. Move alias edit, add substitute, substitute status/actions, slice save/restart/start actions, and any worktree/provider-run actions into the dropdown.
  4. Remove the responsive behavior where wide panes show inline controls and narrow panes use the dropdown.

Web Terminal Changes

  1. In FreeformPaneShellMount.tsx, remove .freeform-agent-id from the visible footer and make alias display non-clickable inline text.
  2. Keep only the slice screen link, if available, before the dropdown trigger.
  3. In freeform-agent-projection.ts, split slice screen link projection from other runtime badges.
  4. In freeform-footer-controls-controller.ts, mount controls into .freeform-footer-menu-panel only.
  5. In freeform.ts, remove or neutralize inline footer control responsive rules so controls cannot re-expand into the old crowded layout.

Local TUI Changes

  1. Update footer part generation to produce alias-only identity plus optional slice action.
  2. Remove provider/model/mode/permission/location/substitute fields from the inline rendered footer slots.
  3. Ensure the local footer action menu follows the same rule: all actions under the dropdown/menu, not inline.

Tests

  1. Update apps/cli/src/split-pane-footer.test.ts in chariox.
  2. Update apps/web/src/terminal/freeform-pane-footer-controller.test.ts, apps/web/src/freeform-footer-controls.test.ts, and apps/web/src/terminal/live-freeform-pane-controller.test.ts in chariox-cloud.
  3. Add assertions that inline controls are absent and menu controls are present at all widths.

Visual Verification

  1. Run the web terminal locally.
  2. Capture screenshots for wide pane local agent, narrow pane local agent, wide pane slice agent with view slice, and narrow pane slice agent with dropdown open.
  3. Paste the screenshots into the conversation for evaluation.
  4. Confirm there is no footer overlap and no crowded clickable targets.
