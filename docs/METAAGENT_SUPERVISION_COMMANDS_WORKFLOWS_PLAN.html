Metaagent implementation plan

Supervision, Command Discovery, Events, and Workflow Guides

This plan brings metaagents closer to the intended model: they plan, delegate, supervise, and complete through Chariox primitives. They should not guess command syntax, silently subscribe to invalid events, or lose visibility into worker activity.

Current conclusion: the recent workflow drill did not prove that can_complete_run should default to true. Directed workflows without loops can complete naturally when terminal node work is complete. The stronger hypothesis is that the metaagent did not build and run a complete workflow shape, and the runtime did not give it enough command guidance or supervision visibility to recover.

Observed Problems

Area Problem Impact
turn_overview Worker activity can be visible in session history while turn_overview returns empty turns. The metaagent believes workers have not executed, then may over-spawn workers or mark the task blocked incorrectly.
Meta prompt flags --wait and --show-reply are advertised by docs, but in the meta command path they are not useful primitives and can be passed as prompt text. Blocking wastes metaagent turns, and full replies can flood context. Metaagents should wake on events and inspect traces selectively.
Command discovery The meta command registry is partial and hand-maintained. Some workflow commands exist in CLI/kernel but are not discoverable or routed for metaagents. Metaagents invent syntax or miss required workflow components such as edges, endpoints, node settings, and run controls.
Event subscriptions subscribe_events accepts arbitrary event strings. Invalid names such as workflow_output succeed but match nothing. The metaagent waits for events that can never arrive.
Workflow guidance Metaagents lack compact tutorials explaining the required workflow parts: nodes, edges, endpoints, run triggers, partial outputs, and final output behavior. The metaagent may create a workflow object without creating a usable workflow execution path.

Clarification: can_complete_run

can_complete_run is not the right primary fix for the observed drill failure.

  • A directed acyclic workflow can complete naturally after the last node completes and no unconsumed messages or pending node runs remain.
  • can_complete_run matters when a node submits explicit final workflow output or should terminate the run early.
  • The drill evidence points instead to incomplete workflow construction, queued or overlapping worker turns, missing workflow-output mechanics, and weak metaagent visibility.
Decision: do not change the default for can_complete_run based on this drill. First fix command exposure, event validation, workflow guides, and supervision visibility.

Implementation Plan

1. Fix turn_overview required

Make turn_overview a reliable supervision surface for metaagents.

  • Include active, queued, completed, and failed worker prompts from runtime session state, not only reconstructed operational history.
  • Read from operational history first, then fall back to session history projection or file-backed session history when operational history has no prompt turns for the target worker.
  • Include latest tool-call summaries, latest assistant output summary, prompt status, provider run id, and whether the worker is busy.
  • Keep turn_blob as the pull-based detailed trace reader so large worker outputs do not flood the metaagent.
  • Add tests that use the real prompt submission path and assert a metaagent can see worker prompt and tool history through turn_overview.

2. Remove Blocking Meta Prompt Flags required

Metaagents should not use --wait or --show-reply. They should delegate, stop their turn, wake on events, and inspect traces.

  • Remove these flags from metaagent command docs and examples.
  • Return a clear meta command error if the flags are used: metaagent prompt does not support blocking reply flags; use events and turn_overview.
  • Keep human CLI behavior separate if humans still need these flags.

3. Build a Complete Chariox Command Catalog required

Replace partial meta command documentation with one complete catalog that covers every Chariox command and subcommand.

  • Catalog fields: command name, aliases, usage, examples, description, tags, natural-language intents, scope, mutation level, metaagent policy, route status, and denial or unavailable reason.
  • Wire search_commands, list_commands, command_docs, and run_command to the same catalog.
  • All commands are discoverable. Not all commands are executable by metaagents.
  • Denied and CLI-only commands must be documented with the reason and recommended alternative.
  • Add parity tests against the CLI command tree and workflow command handlers so command families cannot silently diverge.

4. Validate Event Kinds required

Invalid event subscriptions should fail immediately with suggestions.

  • Create a central event-kind registry.
  • Reject unknown subscribe_events.kind values.
  • Return nearest suggestions for invalid names.
  • List valid event kinds in the tool schema and command docs.
  • Update the metaagent system prompt to name exact required events.

Initial event kinds

  • agent.turn.completed
  • agent.turn.failed
  • runtime.interaction
  • workflow.run.started
  • workflow.run.updated
  • workflow.run.completed
  • workflow.run.failed
  • workflow.run.cancelled
  • workflow.output.final
  • workflow.output.intermediate

5. Improve Workflow Run Visibility required

A metaagent should be able to understand whether a workflow is runnable, running, waiting, blocked, completed, or misconfigured.

  • Expand workflow runs output with active node, node agent, queued or running prompt id, prompt delivery state, blocked reason, missing inputs, failure events, and final-output state.
  • Emit workflow lifecycle metaagent events consistently for run started, run updated, run completed, run failed, and output submitted.
  • Make workflow prompt queue state visible, especially when a workflow prompt is queued behind an active worker turn.
  • Add tests that subscribe a metaagent to workflow events and prove the event wakes or steers the metaagent on real workflow transitions.

6. Add Searchable Guides and Tutorials required

Guides should be runtime-readable documents, not long system-prompt payloads. The metaagent system prompt should instruct the agent to search and read guides before using workflows or building agent apps.

  • Add runtime tools: list_guides, search_guides, and read_guide.
  • Load guide Markdown files from a kernel-owned guide directory.
  • Expose guide title, tags, summary, examples, and command references.
  • Seed guides from successful and failed drills, rewritten as concise operational recipes.

Initial guides

Guide Purpose
workflows/basic-components.md Explains workflow definitions, nodes, edges, endpoints, and how to trigger a run.
workflows/basic-dag.md Shows a minimal directed workflow that flows from implementation to review and completes naturally.
workflows/edges-and-handoffs.md Shows how to connect nodes and pass downstream handoff messages.
workflows/partial-and-final-outputs.md Explains intermediate outputs, final workflow outputs, and when output tools are required.
workflows/events-and-supervision.md Lists valid event kinds and shows how a metaagent waits by ending its turn and waking on events.
workflows/common-failures.md Covers queued workflow prompts, missing endpoints, missing edges, invalid event names, and workers that do not emit workflow output when required.
agent-apps/building-agent-apps.md Shows how to plan, delegate, review, test, and complete an agent app through regular agents or a workflow.

7. Keep Structured Handover Out of Scope defer

Do not add a standardized worker reply or workflow handoff envelope in this pass. First fix the primitives: command discovery, event validation, workflow guidance, and supervision visibility. If the flow is still noisy after those fixes, revisit structured worker/subtask handovers with evidence.

Drill Plan

Drill Prompt Shape Validation
Command Catalog Drill Ask a real metaagent to figure out how to build and run a two-agent workflow without giving command syntax. It must use search/docs and discover nodes, edges, endpoints, run, runs, event subscriptions, and denied/unavailable commands.
Event Validation Drill Ask the metaagent to subscribe to workflow progress and output events. Invalid event names must be rejected with suggestions. Valid names must subscribe and later produce visible events.
Turn Overview Regression Drill Metaagent delegates to a worker, stops, wakes on completion, and inspects the worker. turn_overview must show prompt state, tool calls, and worker output. The metaagent must not mark blocked when worker activity exists.
Direct Agent App Drill Ask a real metaagent to build a small agent app without requiring a workflow. It must delegate, wake on events, inspect evidence, verify via workers, and complete.
Workflow Agent App Drill Ask a real metaagent to build a small agent app by creating and running a suitable workflow. Do not specify the workflow structure. It must read workflow guides, create a complete workflow with nodes, edges where useful, endpoint, run trigger, event subscriptions, supervision, and completion.
Workflow Failure Recovery Drill Give the metaagent a workflow that starts misconfigured or blocked. It must use workflow runs, events, command docs, and guides to diagnose and repair the workflow without direct execution.

Acceptance Criteria

  • Metaagents can discover every Chariox command and subcommand.
  • Denied or unavailable commands are documented with precise reasons.
  • Invalid event subscriptions fail with useful suggestions.
  • turn_overview reliably exposes delegated worker activity.
  • Workflow guides are searchable/readable from metaagent runtime tools.
  • Workflow drills show metaagents building complete runnable workflows.
  • Direct drills show metaagents completing tasks without over-spawning or false blocking.

Implementation Order

  1. Fix turn_overview and remove meta prompt blocking flags.
  2. Add event-kind registry and subscription validation.
  3. Build and wire the complete command catalog.
  4. Add guide tools and seed workflow plus agent-app guides.
  5. Improve workflow runs and workflow lifecycle visibility.
  6. Run the command, event, and turn overview drills.
  7. Run direct agent app drill.
  8. Run workflow agent app drill.
