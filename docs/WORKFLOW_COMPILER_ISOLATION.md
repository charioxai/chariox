# Workflow compiler isolation

The home kernel compiles workflow source in a separate process and exchanges only serialized input and output. Workflow source gets the declarative builder and serialized approved schema data. It gets no host process, files or commands. The kernel selects Node from its operator configuration; caller `node_path` values are ignored.

MP-11 F7 / review R1: validation, apply/run, artifact create/update, registry discovery and stored-source rebuild/update use the same two-job compiler admission limit. Discovery, isolation setup, evaluation and schema replay run without the global app mutex. Before saving a result the kernel rechecks caller authority; artifact updates and source synchronization also reject a changed artifact or workflow snapshot.

Linux uses `/usr/bin/bwrap`. macOS uses Apple's `/usr/bin/sandbox-exec` with a generated Seatbelt profile, the mechanism used by the [official Codex CLI](https://github.com/openai/codex/blob/main/codex-rs/sandboxing/src/seatbelt.rs). Windows and other unsupported hosts remain fail-closed. A missing or unusable isolation backend never starts an unrestricted compiler. On macOS, restore `/usr/bin/sandbox-exec` availability or compile on a supported Linux host with Bubblewrap.

MP-08 / MP-11: Linux mounts individual runtime files read-only. The kernel discovers linked libraries (including shared libnode and ICU data libraries) with an environment-cleared `ldd`, then reads bounded read-only ELF data segments in Node/libnode to identify external built-in module and ICU data file paths. Only recognized Node asset names are admitted; missing assets fail closed. Parent directories, package trees, the workspace and home remain unavailable. Both distribution-packaged Node and official Node use this same boundary. TypeScript does not depend on the Node build: the kernel sends the isolated compiler its vendored amaro 1.1.5 stripper (`apps/kernel/vendor/amaro/`, byte-identical to the one official Node 22.22.1 embeds), which strips types inside the boundary with official Node's `transform` options. Only the source text is passed to it.

MP-08 / MP-11: universal (fat) Node binaries and libraries contribute load commands only from slices matching the architecture Node runs as: a thin Node's own CPU type, or for a universal Node the kernel's CPU type (including under Rosetta). A universal binary without a matching slice fails closed; foreign slices cannot add file reads or unresolved library search paths.

The macOS profile denies operations by default. It permits execution of the selected Node binary, but denies process creation, network access and host IPC. Reads cover only the Node binary, its linked runtime libraries (read by the kernel from Mach-O load commands, so Xcode Command Line Tools are not required), their intermediate symlink names, platform random devices and `/dev/null`. The loader also needs ancestor metadata and access to the root directory itself; this does not grant reads of its children. Writes cover only an atomically created, mode-0700 empty scratch directory. The environment is cleared, inherited non-stdio handles close on exec, OpenSSL operator configuration is replaced by `/dev/null`, and the scratch directory is removed when compilation finishes.

Node receives a V8 heap limit. macOS additionally samples the isolated process's resident memory and physical footprint every five milliseconds and kills and reaps it when either exceeds `script_memory_bytes` plus a 256 MiB allowance for Node's resident baseline and native allocations, mirroring Linux's address-space headroom. Failure to measure a live child fails closed. Sampling can allow a transient overshoot between measurements. CPU and scratch-file size limits are inherited OS resource limits, and a kernel deadline bounds all schema replays and serialized I/O. Input and output pipes are drained concurrently, and output capture is bounded. Linux retains its address-space limit for native allocations.

MP-11 F14: when the kernel is root, the compiler child clears supplementary groups and drops its host UID/GID before executing Bubblewrap. A randomized high UID/GID is selected once per kernel process; its compiler jobs share their task budget without sharing UID 65534 with unrelated host services. The namespace identity remains 65534. This makes its 64-process limit effective; changing the namespace UID alone retains host root's exemption. A nonroot kernel retains its user's inherited process limit because an arbitrary limit of 64 would count unrelated desktop processes. Seccomp still denies process/namespace creation, and memory, time and compiler-concurrency bounds remain common. The selected Node and runtime files must be readable after the privilege drop; private operator paths fail closed without a root fallback.

Schema imports stay in the kernel. Linux opens beneath a held directory with `openat2`; macOS walks beneath a held directory with `openat`, `O_NOFOLLOW` and held directory descriptors for every component. Both reject symlinks and non-regular files, enforce aggregate schema bytes and send only requested schema data to the compiler. The scratch directory has no workspace or schema-root access.

The kernel permits 32 schema-resolution rounds followed by a final compilation. Another unresolved request fails closed, and all rounds share one total deadline.

`apps/cli/scripts/live-macos-workflow-compiler-drill.mjs` drives the built kernel and a rendered TUI through its automation socket on macOS or Linux. Linux can use `--provider-profile` to link an operator-approved existing Codex profile through the product command; no credential files are read by the drill. It validates and runs an ordinary workflow, validates 32 schema imports, and checks refusal of a room agent's compile request through the official Codex CLI. Pass absolute `--kernel`, `--home`, `--workspace-parent` and `--evidence` paths. The home must be below `~/.chariox/dev/`; source fixtures must be outside that directory and the repository. The drill reports verdicts without guard source or raw provider responses. On Linux it requires a new kernel home and removes that home, its disposable runtime identities and fixture workspace after stopping its kernel and TUI. macOS retains the kernel home under the existing operator key-retention contract. Linked provider profiles remain in their original location.
