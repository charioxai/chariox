Metaagent capability plan

Provider MCP and Skill Import for Arroba Grants

Metaagents must grant only Arroba-registered MCPs and skills to regular worker agents. Provider-native MCPs and skills visible to the metaagent are import sources, not the source of truth. This plan makes that rule explicit, adds Claude import parity, and introduces a shared import command for users and metaagents.

Core rule: Arroba registry state is authoritative for grants. If a capability is not installed in Arroba, a metaagent may import it from its provider, verify it with mcp list or skill list, and only then grant it to an owned regular worker.

Surface Status Gap
mcp import codex|opencode Landed through existing provider import parsers. Not centralized with skill import or all-provider sync.
skill import codex|opencode Landed through existing provider skill-root scanners. Not centralized with MCP import or all-provider sync.

Design Principles

  • Only Arroba-installed MCPs and skills can be granted to agents.
  • Provider configs are import sources. Arroba does not mutate provider-owned config during import.
  • Import and grant are separate operations. Import makes a capability available; grant remains per agent.
  • The kernel owns discovery, deduplication, import policy, and protocol results.
  • UI clients render kernel state. Do not add stdin-only startup prompts as the product mechanism.

Phase 1: Metaagent Prompt

Prompt update Required first

Update apps/kernel/src/provider/metaagent_delegation_instructions.md with concise rules:

  • Only Arroba-registered MCPs and skills can be granted.
  • Provider-native tools visible to the metaagent are not automatically grantable.
  • Before granting, run mcp list or skill list.
  • If missing, import from the metaagent's provider, then list/show again.
  • Never grant MCPs or skills to yourself; grant only to owned regular agents.

Phase 2: Claude Import Parity

Claude MCP import

Implement import_claude_mcp_servers and wire mcp import claude [name].

  • Read user MCPs from ~/.claude.json.
  • Read project MCPs from .mcp.json.
  • Respect configured Claude config overrides where Arroba already supports them.
  • Convert supported Claude MCP definitions into ArrobaMcpServerConfig.
  • Skip unsupported auth/OAuth/unknown shapes with explicit reasons.

Claude skill import

Implement import_claude_skills and wire skill import claude [name].

  • Scan personal skills under ~/.claude/skills/<name>/SKILL.md.
  • Scan project skills under .claude/skills/<name>/SKILL.md.
  • Copy full skill directories into Arroba-owned skill roots.
  • Preserve SKILL.md, references, assets, scripts, and metadata.
Claude source notes: Claude Code documentation identifies MCP server locations as ~/.claude.json for user/local scopes and .mcp.json for project scope. Claude Code skills live under personal ~/.claude/skills/ and project .claude/skills/ directories.

Phase 3: Shared Provider Capability Service

Discovery and import service

Refactor Codex, OpenCode, and Claude import paths behind one kernel-owned service.

  • Discover provider MCP candidates.
  • Discover provider skill candidates.
  • Normalize candidate names.
  • Compute MCP definition hashes and skill package hashes.
  • Compare candidates with current Arroba registries.
  • Apply deduplication before writing.
  • Return a structured report for dry-run and import modes.

Deduplication Policy

Case Behavior
Same kind, same normalized name, same hash Collapse duplicates; report identical sources.
Same kind, same normalized name, different hash Choose newest source by source file or directory modified time.
Timestamp unavailable or tied Use deterministic provider/source ordering and report the tie.
Already installed in Arroba Skip by default; do not overwrite existing Arroba entries.
Unsupported provider shape Skip with a typed reason visible in CLI/meta command output.

Phase 4: Slash Command and Protocol

Command

Add a single user-facing import command:

  • /extension import providers [--provider codex|opencode|claude|all] [--kind mcp|skill|all] [--dry-run]

Defaults are --provider all and --kind all.

Protocol

Add versioned local daemon request/response shapes:

  • ImportProviderCapabilitiesRequest
  • ProviderCapabilitiesImported

The report should include imported, already-installed, deduped, skipped, and unsupported entries.

Phase 5: Metaagent Command Discovery

Command docs

Update metaagent command docs and search terms so queries like "grant browser tool", "give worker skill", "missing MCP", or "import provider capability" surface the intended flow.

  1. mcp list or skill list
  2. mcp import <provider> [name] or skill import <provider> [name] when missing
  3. mcp show <name> or skill show <name> to verify
  4. mcp grant <worker> <name> or skill grant <worker> <name>

Validation Drills

Drill A: Real provider import

  • Use real MCPs and skills already installed in Codex.
  • Run /extension import providers --provider codex --kind all --dry-run.
  • Run actual import without --dry-run.
  • Verify mcp list and skill list show the imported entries.
  • Run the import again and verify duplicates are reported as already installed or collapsed.

Drill B: Arroba-only grant path

  • Install one MCP and one skill directly into Arroba that do not exist in provider configs.
  • Spawn a real metaagent and a regular worker.
  • Ask the metaagent to give the worker the needed capability.
  • Pass only if it uses Arroba list/show/grant and does not rely on provider-native tools.

Drill C: Missing capability imported by metaagent

  • Choose a real Codex capability present in Codex but absent from Arroba.
  • Prompt the metaagent at a high level.
  • Pass only if it lists Arroba capabilities, imports from its provider, verifies the result, grants to a regular worker, and supervises worker use.
