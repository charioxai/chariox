TUI and Web Terminal UX Parity Plan

Plan to close the local TUI UX gap against the web terminal for Freeform agent panes, prompt queue and steering behavior, prompt chrome, screen footer, and Waiting Room. Workflow canvas behavior is intentionally out of scope because the TUI has no canvas.

Target outcome

The TUI should feel analogous to the web Freeform terminal where the medium allows it: assistant messages expanded, non-assistant activity blobs collapsed by default, historical turns auto-collapsed, queue/steering visible and actionable, footer state consistent, and Waiting Room rows/footers driven by the same runtime facts.

Current Remediation Plan

  1. Make the queue a single Web-like surface. Done: queued prompts render through the dedicated strip, live queued prompt rows are not duplicated in transcript scrollback, and successful queued-prompt lifecycle notices are filtered from agent-pane history.
  2. Normalize queue lifecycle rendering. Done: steering renders one intentional non-turn-tracking user echo, cancellation removes the queued item without stale transcript residue, and steering/cancelling feedback stays transient in the strip.
  3. Fix queue keyboard control. Done for focused queue selection, deterministic TUI input handling, automation controls, raw stdin escape-prefix shortcut routing, and saved post-shortcut narrow/wide terminal captures.
  4. Rebuild queue strip layout. Done: focused queue rows use compact [S]/[C] controls, prompt/meta truncation, and generated 80x24/120x32 captures prove the strip stays bounded.
  5. Upgrade collapsed blob presentation. Done for the core TUI projection: collapsed blobs have useful headers, type/status metadata, compact summaries, loading/error states, live PTY assertions, screenshot-backed narrow/wide terminal captures, and loaded lazy-history content detail.
  6. Apply the same compact layout rules to Waiting Room and footer actions. Done for row/footer formatting, session-row truncation tests, live attached transition validation, and generated terminal capture at 80x24 and 120x32 widths.
  7. Add parity drills as invariants. Done for behavior assertions in the seeded TUI/Web fixture: queued prompt appears once, queued notices are excluded from transcript scrollback, raw shortcut steering removes stale rows, blobs expose collapsed/expanded state, turn collapse still works in focused tests, Waiting Room rows/footer hints render without overlap, and generated emulator-style terminal captures are saved as a second layer.
  8. Keep this below clients where possible. Done for this parity plan: queue projection, notice filtering, blob summaries, history loading, footer state, and Waiting Room rows stay in shared TUI/kernel-client paths with no parallel prompt, history, permission, attachment, or relay authority path. No serialized protocol shape change was required for the TUI parity slices.

Manual visual checklist

  • Assistant messages remain expanded and readable.
  • Tool, reasoning, status, and history blobs start collapsed.
  • Old completed turns collapse while the active/latest turn stays expanded.
  • Loading older history does not lose blob or turn collapse state.
  • Queued prompt strip appears with prompt preview, status, attachment count, steer, and cancel.
  • Steer and cancel work through keyboard and mouse.
  • Steered prompt appears in the correct chronological position without creating a new active turn.
  • Pane footer shows the same runtime facts as web in TUI form: status, alias, provider, model, mode, permission, runtime placement, and slice/substitute hints.
  • Screen footer prioritizes fatal errors, active prompt, queue depth, status line, connection, and hotkeys consistently.
  • Waiting Room rows show working/done/idle sessions, remote and slice next actions, and footer hints matching web semantics where applicable.

Non-Goals

  • Do not add a workflow canvas to TUI.
  • Do not add web-only buttons under TUI agent panes.
  • Do not make the relay or web app the runtime authority for any of this behavior.
  • Do not create a separate prompt, permission, attachment, history, or relay path for native provider TUIs.
