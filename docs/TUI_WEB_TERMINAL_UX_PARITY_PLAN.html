TUI and Web Terminal UX Parity Plan

Plan to close the local TUI UX gap against the web terminal for Freeform agent panes, prompt queue and steering behavior, prompt chrome, screen footer, and Waiting Room. Workflow canvas behavior is intentionally out of scope because the TUI has no canvas.

Target outcome

The TUI should feel analogous to the web Freeform terminal where the medium allows it: assistant messages expanded, non-assistant activity blobs collapsed by default, historical turns auto-collapsed, queue/steering visible and actionable, footer state consistent, and Waiting Room rows/footers driven by the same runtime facts.

Parity Matrix

Area Web Behavior TUI State Gap
Transcript blobs Assistant, user, and error entries are expanded. Tool, reasoning, status, and history blobs are collapsed by default. Blob collapse policy is shared through transcript lineage helpers and covered by TUI display tests. Aligned.
Turn lifecycle Active turns stay expanded; completed historical turns can collapse to a prompt plus final assistant summary. Historical collapse and latest-turn preservation exist in agent pane state. Mostly aligned; focused tests cover active turns, completed collapse, and refresh preservation.
History loading Per-agent history state tracks loading, older-page loading, cursors, and minimum loader visibility. TUI loads history pages and backfills older history to preserve renderable count after refresh. Needs user-visible loading/error parity and tests for expansion preservation.
Queued prompts Dedicated queued-prompt strip shows status, text, attachments, steer, and cancel. Queued prompts render in transcript scrollback and in a pane interaction strip above the footer. Aligned with TUI-specific Alt+S/Alt+C keyboard actions for the focused agent's first queued prompt.
Steering echo Steered queued prompts append a non-turn-tracking user echo and dedupe against kernel echoes. TUI appends a non-turn-tracking echo, overlays optimistic queue state, reconciles returned session state, and skips matching kernel prompt echoes. Aligned.
Agent pane footer Status badge, alias edit, runtime placement, config menu, substitute actions, slice link, and turn clock. Status badge plus alias/meta/slice label. Render slots for provider/model/mode exist but formatter mostly omits them. Needs footer state expansion using TUI-appropriate text and menus.
Prompt area Drafts, attachments, history navigation, send/stop behavior, failed-submit restore, and queued-submit no-echo. Comparable draft, attachment, history, focus retention, failed-submit restore, and queue-aware submit behavior exists. Mostly aligned; queue depth and active prompt hints need stronger pane/screen visibility.
Screen footer Status region reports connect/session/focus/action feedback and Waiting Room hints. TUI derives active prompt, queue depth, status line, hotkeys, connection, and sync footer text. Needs consistent copy and priority order against web footer semantics.
Waiting Room Richer recent-session picker, session tree, side panels, web-only unattached-agent surfaces, and modal actions. Compact rows for start, sessions, external provider sessions, remotes, slices, terminals, and theme. Needs state priority parity; web-only unattached-agent list remains intentionally omitted.

Implementation Plan

  1. Add focused parity fixtures for transcript entries and turns. Cover assistant/user/error expanded by default, non-assistant blobs collapsed by default, active turn expanded, completed older turns collapsed, and history refresh preserving collapse state.
  2. Normalize the TUI transcript display terminology. Keep public behavior stable, but make the internal state distinguish collapsed turn IDs from expanded turn IDs so future changes do not invert behavior accidentally.
  3. Add a TUI queued-prompt strip above the pane footer or prompt area. It should use queuedPromptProjectionForAgent, show status/text/attachment count, and expose steer/cancel through both keyboard and mouse.
  4. Preserve existing queued-prompt transcript rows as scrollback context unless the strip fully replaces them without losing historical clarity. If both remain, avoid duplicate action affordances fighting each other.
  5. Align queued-prompt actions with web behavior: optimistic steering/cancelling state, stale disabled reason, returned session reconciliation, visible steered prompt echo, and focus returning to the prompt area.
  6. Expand the TUI agent footer formatter to include provider, model, variant/effort, mode, permission, runtime placement, substitute summary, and active turn clock where there is space. Compress predictably at small widths.
  7. Keep web-only footer buttons out of the TUI, but provide analogous commands or keyboard paths for config, alias edit, substitute actions, and slice actions.
  8. Tighten prompt chrome so active prompt ID plus queue depth appears in the screen footer consistently, and queued submissions never render as normal user turns.
  9. Align Waiting Room row semantics with web: sorting by recent activity, active work markers, unread idle output, active/queued prompt counts where available, remote/slice recovery next actions, and footer hints.
  10. Document intentional TUI differences: no workflow canvas, no web side panels, no web-only unattached-agent list, and no pane-button row under agents.

Manual visual checklist

  • Assistant messages remain expanded and readable.
  • Tool, reasoning, status, and history blobs start collapsed.
  • Old completed turns collapse while the active/latest turn stays expanded.
  • Loading older history does not lose blob or turn collapse state.
  • Queued prompt strip appears with prompt preview, status, attachment count, steer, and cancel.
  • Steer and cancel work through keyboard and mouse.
  • Steered prompt appears in the correct chronological position without creating a new active turn.
  • Pane footer shows the same runtime facts as web in TUI form: status, alias, provider, model, mode, permission, runtime placement, and slice/substitute hints.
  • Screen footer prioritizes fatal errors, active prompt, queue depth, status line, connection, and hotkeys consistently.
  • Waiting Room rows show working/done/idle sessions, remote and slice next actions, and footer hints matching web semantics where applicable.

Non-Goals

  • Do not add a workflow canvas to TUI.
  • Do not add web-only buttons under TUI agent panes.
  • Do not make the relay or web app the runtime authority for any of this behavior.
  • Do not create a separate prompt, permission, attachment, history, or relay path for native provider TUIs.
