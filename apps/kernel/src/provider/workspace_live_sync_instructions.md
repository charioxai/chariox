Arroba workspace live sync is enabled for the selected repository/worktree roots only. Direct filesystem writes inside those roots are unavailable. Use the Arroba MCP tools for synced workspace file access; other repositories outside the synced roots are not part of live sync and may be edited normally. Do not interpret live sync as a global filesystem restriction. If the user asks you to modify an absolute path outside the synced roots, use your provider-native shell/bash tool normally and do not just print a command. In OpenCode, native edit/write/patch tools may be disabled while managed live sync is active, but provider-native bash remains available for outside-repository writes and may ask for `external_directory` and `bash` approval before executing. In OpenCode, call the live-sync tools by their `arroba_*` names: `arroba_read_artifact`, `arroba_write_artifact`, `arroba_edit_artifact`, `arroba_delete_artifact`, and `arroba_move_artifact`; use `arroba_write_artifact`/`arroba_edit_artifact` for file modifications inside the synced roots. In Codex these may appear as `mcp__arroba__read_artifact`, `mcp__arroba__write_artifact`, `mcp__arroba__patch_artifact`, etc. Legacy names like `arroba.read_artifact`, `arroba.write_artifact`, and `arroba.edit_artifact` are also accepted. Avoid any bare or OpenCode-prefixed `apply_patch` name because it refers to the native patch tool in some providers and may be disabled while workspace live sync is active. To read synced files, call the read tool with a workspace-relative `path` and optional `domain: "text"`. To create or overwrite synced text files, call the write tool with `path`, `content_text`, and `domain: "text"`; omit `snapshot_id` when creating a new file. To edit existing synced text, first read it, then call the edit tool with the returned `snapshot_id`, plus `old_text` or `range`, and `new_text`; for patch-shaped edits outside OpenCode, call the workspace live sync patch tool with `patch_text`; to delete or move synced text files, call the delete or move tool. For synced non-text/binary artifacts, use `domain: "opaque"` and `content_base64`; opaque deletes and moves operate on the whole file and must not include `old_text`, `new_text`, or text patch content. If an edit is rejected, reread the artifact, reconcile with current content, and retry through Arroba.

When workspace live sync approval is required, Arroba will interrupt the mutating tool call and surface the approval UI itself. Do not stop to ask for write permission in freeform text and do not use `request_popup` as a substitute for workspace live sync approval. Attempt the workspace live sync operation normally and let Arroba gate it.
