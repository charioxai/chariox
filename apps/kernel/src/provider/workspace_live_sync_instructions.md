Chariox workspace live sync is enabled for the selected repository/worktree roots only. Direct filesystem writes inside those roots are unavailable. Use the Chariox MCP tools for synced workspace file access; other repositories outside the synced roots are not part of live sync and may be edited normally. Do not interpret live sync as a global filesystem restriction. If the user asks you to modify an absolute path outside the synced roots, use provider-native edit/write/patch or shell/bash tools normally and do not just print a command. OpenCode may ask for `external_directory`, edit/write/patch, and bash approval before executing outside-repository writes; writes inside synced roots are rejected unless Chariox has installed a selective platform write fence. In OpenCode, call the live-sync tools by their `chariox_*` names: `chariox_read_artifact`, `chariox_write_artifact`, `chariox_edit_artifact`, `chariox_delete_artifact`, and `chariox_move_artifact`; use `chariox_write_artifact`/`chariox_edit_artifact` for file modifications inside the synced roots. In Codex these may appear as `mcp__chariox__read_artifact`, `mcp__chariox__write_artifact`, `mcp__chariox__patch_artifact`, etc. Legacy names like `chariox.read_artifact`, `chariox.write_artifact`, and `chariox.edit_artifact` are also accepted. Avoid any bare or OpenCode-prefixed `apply_patch` name for synced-root changes because it refers to the native patch tool in some providers. To read synced files, call the read tool with a workspace-relative `path` and optional `domain: "text"`. To create or overwrite synced text files, call the write tool with `path`, `content_text`, and `domain: "text"`; omit `snapshot_id` when creating a new file. To edit existing synced text, first read it, then call the edit tool with the returned `snapshot_id`, plus `old_text` or `range`, and `new_text`; for patch-shaped edits outside OpenCode, call the workspace live sync patch tool with `patch_text`; to delete or move synced text files, call the delete or move tool. For synced non-text/binary artifacts, use `domain: "opaque"` and `content_base64`; opaque deletes and moves operate on the whole file and must not include `old_text`, `new_text`, or text patch content. If an edit is rejected, reread the artifact, reconcile with current content, and retry through Chariox.

When workspace live sync approval is required, Chariox will interrupt the mutating tool call and surface the approval UI itself. Do not stop to ask for write permission in freeform text and do not use `request_popup` as a substitute for workspace live sync approval. Attempt the workspace live sync operation normally and let Chariox gate it.
