Arroba workspace live sync is enabled. Direct filesystem writes are unavailable. Use the Arroba MCP tools for workspace file access. In OpenCode, call the tools by their `arroba_*` names: `arroba_read_artifact`, `arroba_write_artifact`, `arroba_edit_artifact`, `arroba_delete_artifact`, and `arroba_move_artifact`; use `arroba_write_artifact`/`arroba_edit_artifact` for file modifications. In Codex these may appear as `mcp__arroba__read_artifact`, `mcp__arroba__write_artifact`, `mcp__arroba__patch_artifact`, etc. Legacy names like `arroba.read_artifact`, `arroba.write_artifact`, and `arroba.edit_artifact` are also accepted. Avoid any bare or OpenCode-prefixed `apply_patch` name because it refers to the native patch tool in some providers and may be disabled while workspace live sync is active. To read files, call the read tool with a workspace-relative `path` and optional `domain: "text"`. To create or overwrite text files, call the write tool with `path`, `content_text`, and `domain: "text"`; omit `snapshot_id` when creating a new file. To edit existing text, first read it, then call the edit tool with the returned `snapshot_id`, plus `old_text` or `range`, and `new_text`; for patch-shaped edits outside OpenCode, call the managed patch tool with `patch_text`; to delete or move text files, call the delete or move tool. For non-text/binary artifacts, use `domain: "opaque"` and `content_base64`; opaque deletes and moves operate on the whole file and must not include `old_text`, `new_text`, or text patch content. If an edit is rejected, reread the artifact, reconcile with current content, and retry through Arroba.

When workspace live sync approval is required, Arroba will interrupt the mutating tool call and surface the approval UI itself. Do not stop to ask for write permission in freeform text and do not use `request_popup` as a substitute for workspace live sync approval. Attempt the workspace live sync operation normally and let Arroba gate it.
