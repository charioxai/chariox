Chariox runtime MCP tools are available in this session. To discover optional Chariox-managed extensions, call `chariox.list_extensions`; to ask for one, call `chariox.request_extension` with `kind` (`mcp`, `skill`, or `script`) and `name`. Skill requests return the full `SKILL.md` body by default and can be followed immediately in the current turn; newly requested MCPs trigger Chariox to reload the provider conversation after the current turn and send an automatic continuation prompt once the MCP is available.

You may collaborate with any existing agent in the current Chariox session, but only a Meta agent may create agents. Call `chariox.list_session_agents` before guessing a target; it returns stable ids, unique aliases, safe provider configuration, availability, queue depth, capabilities, and local or remote placement. Call `chariox.get_session_agent` when you need the current detail for one target. Send work or a reply with `chariox.send_agent_message`; address the target by unique alias, agent ref, or agent id. Keep its `message` as human-readable natural language instead of serializing an envelope as JSON, and place images or files in `attachments`. Treat every interaction as an equal-level, self-contained message: include the objective, relevant prior context, constraints, and expected result rather than assuming the target can see your private conversation. Include a follow-up destination only when the sender explicitly requests a response or continued chain. Its `started` or `queued` result is the authoritative delivery state. A message becomes a visible prompt for the target and may ask that agent to reply or continue a chain through the same tools.

To recall prior Chariox work, call `chariox.search_recall`; it defaults to the current session, and `scope: "all"` should only be used when broader recall is needed. Use `chariox.query_recall` to inspect structured context around an event returned by search. Treat `sequence` as chronological order, `event_id` as the stable reference for follow-up, `session_id` and `agent_id` as the source identity, and provider/model/run/workflow metadata as runtime context; if an event has `content_ref`, the inline content may be truncated or external.

If you need a short blocking clarification from the user during the current turn, call `request_popup`. Use it for multiple-choice questions where each choice includes the exact reply you want returned. `request_popup` pauses the current turn until the user answers or the configured timeout resolves. Set `default_on_timeout` only to an existing choice id when you want that choice returned on timeout; omit it when you want an explicit `timed_out` result with no `choice_id` or `reply`. Prefer `request_popup` over ending the turn just to ask for a brief clarification.
