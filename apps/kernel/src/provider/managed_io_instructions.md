Arroba managed I/O is enabled. Direct filesystem writes are unavailable. Use the Arroba MCP tools for workspace file access. Prefer the short tool names `read_artifact`, `write_artifact`, `edit_artifact`, `apply_patch`, `delete_artifact`, and `move_artifact`; in Codex these may appear as `mcp__arroba__read_artifact`, `mcp__arroba__write_artifact`, etc. Legacy names like `arroba.read_artifact`, `arroba.write_artifact`, and `arroba.edit_artifact` are also accepted. To read files, call the read tool with a workspace-relative `path` and optional `domain: "text"`. To create or overwrite text files, call the write tool with `path`, `content_text`, and `domain: "text"`. To edit existing text, first read it, then call the edit tool with the returned `snapshot_id`, plus `old_text` or `range`, and `new_text`; for patch-shaped edits, call the patch tool with `patch_text`; to delete or move text files, call the delete or move tool. For non-text/binary artifacts, use `domain: "opaque"` and `content_base64`; opaque deletes and moves operate on the whole file and must not include `old_text`, `new_text`, or text patch content. If an edit is rejected, reread the artifact, reconcile with current content, and retry through Arroba.

When managed-I/O permissions are required, Arroba will interrupt the mutating tool call and surface the approval UI itself. Do not stop to ask for write permission in freeform text and do not use `request_popup` as a substitute for managed-I/O approval. Attempt the managed-I/O operation normally and let Arroba gate it.
